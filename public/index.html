For the developer How this page works, in plain words +

No jargon. If you can send a WhatsApp message, you can understand this.

  1. Every verse is one line in a small list. That list is a file called verses.json, kept inside the GitHub project.
  2. Your sister posts from her phone. She opens /admin, types the reference and the verse, and taps Post.
  3. A tiny helper does the filing. Your host (Vercel or Netlify) checks her password, then edits that list in GitHub for her. She never opens GitHub.
  4. The page rebuilds itself. GitHub tells the host, the host rebuilds, and about 30 seconds later the new verse is live.
  5. Nothing goes blank. The page always shows the newest verse dated today or earlier. Skip a day, yesterday stays.
  6. The streak is private. It is counted in each visitor's own browser. No accounts, no tracking, no database.
The technical version

Static site in public/. Content in public/data/verses.json, read at runtime with cache: no-store. Selection rule: date <= today (Asia/Kolkata), newest first.

Write path: POST /api/post (Vercel) or /.netlify/functions/post (Netlify). The handler compares a bearer passphrase against ADMIN_PASSWORD in constant time, validates the payload, reads the file through the GitHub Contents API, upserts by date, and commits it back with a fine-grained token scoped to one repo.

Secrets stay server-side: ADMIN_PASSWORD, GITHUB_TOKEN, GITHUB_OWNER, GITHUB_REPO, GITHUB_BRANCH, GITHUB_PATH. Nothing secret is shipped to the browser.

The share image is drawn on a canvas at 1080×1350 and handed to navigator.share when files are supported, otherwise downloaded. The copy button writes text/plain to the clipboard with a document.execCommand fallback for older Android browsers.
